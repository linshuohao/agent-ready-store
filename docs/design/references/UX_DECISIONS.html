04 / 已確認設計決策

保留方案對比、有效要求與取捨。具體數值型 Token、字體、斷點仍待下一階段設計。

UX-01ACCEPTED

首页信息架构

C · Catalog-first 首页

讨论方向
品牌营销型首页 / 纯商品列表 / 轻量品牌区＋商品目录
最终要求
首页保留克制的品牌介绍，搜索、筛选、排序与商品网格为主体。无需独立营销 Landing Page。
取舍理由
兼顾商品发现效率与视觉完成度，避免大幅增加营销内容制作成本。
UX-02ACCEPTED

商品详情

A · 独立详情页

讨论方向
独立详情页 / 快速预览弹窗 / 侧边详情面板
最终要求
独立页面展示商品身份、价格、规格、库存或可购买状态、评论概览与评论分页。首页可保留轻量快捷加购。
取舍理由
避免在有限空间中承载复杂规格和分页评论，页面职责更清楚。
UX-03ACCEPTED

购物车形态

B · 独立 Cart Page

讨论方向
购物车 Drawer / 独立页面＋轻反馈 / Drawer＋独立页面
最终要求
加入购物车后使用轻量反馈，不强制跳转；通过顶部入口打开独立购物车，处理数量、移除和异常状态。
取舍理由
减少多处购物车编辑 UI 的重复与同步负担。
UX-04ACCEPTED

Agent Handoff 入口

B · 直达共享 Checkout

讨论方向
先到购物车 / 直达共享 Checkout / Agent 独立交接页
最终要求
Agent 生成的 Handoff Link 直接进入普通购物共享的 Checkout，展示完整订单摘要和编辑入口；最终由 Human 明确确认。
取舍理由
减少不必要跳转，保持同一套结账行为和授权边界。
UX-05ACCEPTED

Checkout 编辑

B · 返回原 Cart 编辑

讨论方向
Checkout 内联编辑 / 原 Cart 编辑后返回 / Checkout 仅改数量
最终要求
Checkout 的订单摘要原则上只读；编辑入口打开当前对应购物车，编辑完成回到 Checkout 并重新报价。Agent 来源与购物车身份必须保留。
取舍理由
复用购物车管理能力，避免 Checkout 承载完整购物车编辑职责。
UX-06ACCEPTED

导航与响应式

A · 顶部导航＋响应式

讨论方向
统一顶部导航 / 移动端底部 Tab / 侧边导航＋移动菜单
最终要求
桌面与移动端共用信息架构；顶部保留品牌、搜索、购物车入口。桌面商品网格和 Checkout 可更宽，移动端按空间重排，Checkout 优先单栏。
取舍理由
简化导航，突出当前只有少量一级功能的购物闭环。
EX-01ACCEPTED

报价变化

Checkout Inline Alert＋再次确认

讨论方向
页内提示 / 模态弹窗
最终要求
Checkout 页面内显著展示报价或关键购买内容的变化，更新明细，要求 Human 再次确认；不得按新结果静默成单。
取舍理由
避免不必要弹窗，同时保留可见的报价上下文。
EX-02ACCEPTED

库存不足

保留购物车、标记问题商品

讨论方向
保留并提示 / 直接跳转购物车
最终要求
保留现有 Cart，定位并标注缺货或不可购买商品，提供编辑入口；不删除商品、不自动部分下单。
取舍理由
符合整笔购买成功或失败的业务决策，便于用户恢复。
EX-03ACCEPTED

Handoff 过期

独立过期状态

讨论方向
独立状态 / 回首页 Toast
最终要求
旧链接不可继续 Checkout；单独说明过期，并提供返回商城或重新发起 Agent 购物的指引。
取舍理由
清晰揭示访问失效，避免误导用户继续购买。
WF-01ACCEPTED

原型覆盖

A · 5 个 Wireframe＋3 个视觉稿

讨论方向
5+3 / 全部桌面移动双线框 / 仅三个关键线框
最终要求
五个核心页面：列表首页、详情、购物车、Checkout、订单结果；三张代表性视觉稿：列表首页、详情、Checkout；异常状态用局部状态稿。
取舍理由
覆盖关键业务链路，控制重复制作成本。
V-01ACCEPTED

视觉语言

黑白极简 Monochrome Minimal Commerce

讨论方向
Editorial Minimal / Modern Commerce / AI Futuristic；最终调整为黑白极简
最终要求
以白、黑、灰、排版、留白和细边框为主，突出商品与价格，高对比强调主要操作；必要语义色仅用于状态表达，不单靠颜色区分。
取舍理由
符合偏好的清爽对话式视觉语言，避免 AI 风格装饰干扰购物。
V-02ACCEPTED

设计稿形式

HTML + CSS

讨论方向
静态图片 / 设计工具 / HTML-CSS
最终要求
用可渲染的 HTML/CSS 提供线框和代表性视觉稿，可做必要状态切换及响应式预览；不连接真实业务服务，不成为第二套商城。
取舍理由
直观可看，利于评审和复用视觉规范，避免把原型变成重复开发。
UI-01ACCEPTED

界面语言

仅繁体中文 zh-TW

讨论方向
繁体＋英文切换（曾提出并确认）→ 仅繁体（最新修订）
最终要求
商城系统 UI 文案使用繁体中文，保留商品 Mock 原始字段内容；不做语言切换、翻译服务或国际化资源管理。
取舍理由
跟随本次题目与 Mock 数据语言，降低超出作业必要范围的实现成本。
QA-01ACCEPTED

验收策略

人工 Design Review＋关键自动检查

讨论方向
仅人工 / 人工＋关键自动化 / 全面视觉回归
最终要求
人工审阅布局、视觉层级、状态与交互；关键用户流与基本响应式做自动化检查；不强制建设大型视觉回归矩阵。
取舍理由
兼顾可信交付与时间约束。
DS-01ACCEPTED

设计入口

单一 HTML Design Preview

讨论方向
分散预览 / 单一入口
最终要求
一个可直接打开的设计展示 HTML，含 5 个线框、3 个视觉稿、异常状态、Tokens 与导航。与最终 Project Showcase 分开。
取舍理由
便于 Human Review 和后续 Codex 理解，避免散落的设计资产。
