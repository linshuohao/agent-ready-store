# documentation-delivery-hub Specification

## Purpose

为项目交付建立统一的静态阅读体验，使面试官能从产品展示进入现有 Markdown 设计、决策及验证依据，再返回原展示位置，同时保持文档唯一来源、历史状态和受控分发范围，不改变商城业务契约。

## Requirements

### Requirement: 统一交付入口
站点 SHALL 提供产品体验、四章展示、主题文档和交付证据入口，README SHALL 保持可独立阅读并提供站点入口。

#### Scenario: 从展示深入设计
- **WHEN** 读者从产品 Demo 打开库存取舍与交易设计
- **THEN** 站内正常显示对应正文，并可继续进入已指定的验证依据

### Requirement: 同站双模式
站点 SHALL 在同一内容与部署体系下保留项目导览与演示模式；两者共享文档与证据目标，但分别使用自由阅读和四章讲解的布局及导航，不强制合并为单页。

#### Scenario: 两种入口阅读同一设计
- **WHEN** 读者分别从项目导览与演示模式打开交易设计
- **THEN** 两个入口进入同一正文页面，演示来源可返回原章节与步骤，项目导览来源保留正常主题导航

### Requirement: 原文渲染与唯一来源
站点 MUST 从显式纳入的仓库文件生成正文，支持标题、表格、列表、代码、图片、details、显式锚点与 Mermaid；不可要求手工维护同一设计的第二份全文。

#### Scenario: 更新设计文件
- **WHEN** 纳入的 Markdown 正文变更并重新构建
- **THEN** 阅读页反映变更，保留来源路径，Mermaid 正常呈现或以明确错误阻止验收

### Requirement: 连续导航与返回
站点 SHALL 提供主题导航、文内目录和来源；从展示进入文档时保留返回章节及步骤，支持直接进入、刷新和浏览器后退。

#### Scenario: 深入阅读后返回
- **WHEN** 读者由 Demo 某一步进入设计，再进入关联决策并返回展示
- **THEN** 回到原章节和步骤，存储可用时恢复位置；直接进入文档时不伪造此前路径

### Requirement: 路径与锚点可验证
构建 MUST 按源文件路径解析 Markdown、图片及受控 HTML 链接，检查纳入目标和实际输出锚点；无效内部链接不得静默重定向首页。

#### Scenario: 锚点失效
- **WHEN** 文档链接的片段不存在于目标产物
- **THEN** 检查失败并报告来源文件、目标及片段

### Requirement: 内容分发边界
构建 MUST 仅输出清单批准的文档和资源，默认排除原始 references、凭证、未批准对话和仓库元数据；历史与未批准状态不得被改写为当前已批准。

#### Scenario: 引用受限原件
- **WHEN** 纳入文档引用未获分发授权的原始需求
- **THEN** 页面说明原件未分发，构建产物不包含原件内容或可下载副本

### Requirement: 静态运行与兼容入口
站点 SHALL 在无需商城 API 的静态 HTTP 环境中阅读已构建内容；旧入口使用明确兼容映射，实际商城与外部证据标明网络和权限前提。

#### Scenario: 商城未启动
- **WHEN** 读者本地预览静态站且商城服务不可用
- **THEN** 文档、导航、图示仍可阅读，实际购物入口不被标为已连接或已验收
