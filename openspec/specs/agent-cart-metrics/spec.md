# agent-cart-metrics Specification

## Purpose

为本地 Demo 提供可核对的有效 Agent 购物车创建事实及按车去重汇总，防止重试、编辑、交接或生命周期变化放大或撤销历史数量；明确该数量的业务含义，不将演示数据当作真实运营目标或独立顾客统计。

## Requirements

### Requirement: 有效创建事实及去重

系统 SHALL 仅将可信 Agent 流程成功创建、初始非空且商品/数量均有效的 Cart 计作有效创建，按 Cart ID 一车一次。普通 HUMAN 车、失败或回滚创建不计入。系统 MUST 保留该创建事实，不因后续编辑为空、售罄、过期、成交、响应丢失或重启撤销，也不因重试/读取/分享新增次数。

#### Scenario: 创建后生命周期变化
- **WHEN** 成功 Agent 建车随后修改、删空、分享、到期或成交，并多次重试原创建
- **THEN** 有效创建总数仅增加一次，库存仅在独立购买成功时改变

#### Scenario: 非有效创建
- **WHEN** 普通 Web 建车、Agent 空车/非法创建、事务回滚或同键异内容冲突
- **THEN** 不增加有效 Agent 创建数；不同 ID 的合法 Agent 新车各计一次，不声称识别重复意图

### Requirement: 受控汇总与验收边界

系统 SHALL 提供本地受控只读汇总方式，按数据库已提交的有效创建事实输出数量和统计口径，不输出车 Token 或个人/订单明细，不新增公开指标 API 或 MCP 工具。系统 MUST 将 Demo 口径验证与上线一个月1000车的运营目标区分，不将测试数据宣称为业务达标。

#### Scenario: 可核对的本地统计
- **WHEN** 在隔离库执行有效/无效创建和重试后运行只读汇总
- **THEN** 输出可与唯一 Cart 事实核对的数量；重启前后相同事实得到相同数量，无写入、清理或秘密输出
