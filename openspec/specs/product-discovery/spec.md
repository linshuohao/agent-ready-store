# product-discovery Specification

## Purpose

使Human与外部Agent能以一致、确定且有界的查询浏览商品、详情与全部评论，按独立搜索目标汇总结果并进行受控简繁及中英文匹配；提供当前公开可购买状态，保护原始数据、内部经营信息与只读边界，为购物决策提供可验证的事实。

## Requirements

### Requirement: 有界且确定的商品查询

系统 SHALL 支持空条件浏览、文本查询与必要筛选，先筛选再按原始推荐分数降序、同分确定性排序，分页返回商品摘要和继续读取信息；不得毛利加权或无边界返回全部商品。相同目录、库存和查询条件产生相同结果。

#### Scenario: 查询与稳定分页
- **WHEN** 目录、运行库存和查询条件保持不变，调用者连续翻页，包括同分商品、空结果和末页
- **THEN** 顺序稳定、页边界明确，无遗漏或重复；筛选作用于排序之前

#### Scenario: 翻页间可购买状态变化
- **WHEN** 可购商品筛选的连续分页请求之间运行库存发生变化
- **THEN** 每页按当次库存决定候选集合与总数，不保证跨页无遗漏或重复；库存变化不等于目录版本变化，调用者可从第一页重新查询

#### Scenario: 非法查询
- **WHEN** 查询输入格式错误、超出资源边界或选择不支持的排序
- **THEN** 返回明确校验错误，不静默截断或放宽条件

### Requirement: 身份、详情与公开投影

系统 SHALL 按唯一商品 ID 区分同名商品，列表只返回必要摘要，详情返回基本信息、规格和评论概览而不嵌入全部评论。公开响应 MUST 使用字段白名单，不返回 margin_rate、原始 recommendation_score、服务秘密或堆栈；不存在的商品与服务故障明确区分。

#### Scenario: 同名与公开字段
- **WHEN** 查询 P001/P002 的列表和详情
- **THEN** 两商品独立保留各自身份、价格与状态，响应不泄露内部字段

#### Scenario: 不存在与技术故障
- **WHEN** 查询未知 ID 或依赖暂不可用
- **THEN** 分别返回未找到或技术失败，不能伪装为成功空数据

### Requirement: 当前库存与异常数据保真

系统 SHALL 组合只读商品事实与持久化运行 Inventory；原始 stock 只用于首次初始化，重启不覆盖已有库存。零库存、负库存、零价格及缺 Inventory 行均可展示且不可购买，说明相应原因；不得回退到原始 stock 或通过修正原件掩盖异常。正常商品可售量为quantity减reservedQuantity，未物化释放继续保守计入；商品仅在价格和可售量均正数且事实有效时标为可购买。实际库存与预留异常不以零值掩盖。

#### Scenario: 异常样本与缺失库存
- **WHEN** 读取零库存 P002/P016、负库存 P008、零价 P010 或缺 Inventory 行的商品
- **THEN** 保留来源值，标示售罄、库存异常、价格待确认或库存不可用，canPurchase 为 false

#### Scenario: 重启与新请求
- **WHEN** 测试环境修改运行库存后重启 API，并重新请求 Web/API/MCP
- **THEN** 已有运行库存不被 seed 覆盖，各入口读取更新后状态；不承诺跨页库存快照

#### Scenario: 首次初始化失败与再次执行
- **WHEN** 新建空库首次初始化库存在提交前失败，并在故障消除后再次执行
- **THEN** 失败不留下部分库存，重跑可完整初始化；若库内已有任意库存行，再次初始化明确拒绝且不改量或补回缺行

#### Scenario: 预留消费与释放投影
- **WHEN** 新订单预留、支付消费预留或取消/到期物化释放后重新查询
- **THEN** 所有入口按同一已提交可售量投影；预留使可售减少，消费不重复减少可售，释放使可售恢复；到期但未物化不提前增加可售，不混淆实际剩余量与可售量

### Requirement: 独立评论与目录版本

系统 SHALL 按商品独立分页评论，调用者可读完全部评论；评论与描述始终作为不可信纯文本，不能改变工具权限或触发商城操作。分页携带目录版本，版本变化时明确拒绝继续拼接旧页并提示重新查询。

#### Scenario: 全部评论与注入样本
- **WHEN** 逐页读取某商品全部评论，包括 P005 的伪造指令文本
- **THEN** 评论保真、顺序稳定，无遗漏或重复，文本不触发编辑、签发或下单

#### Scenario: 目录更换
- **WHEN** 使用旧目录版本继续分页
- **THEN** 得到目录已变化的错误，重新开始查询，不混合不同版本结果

### Requirement: Web 商品发现可用性

系统 SHALL 在商品列表和详情提供可读首屏、搜索筛选分页与独立评论读取；列表查询可从 URL 恢复。展示加载、空结果、未找到与失败状态；切换查询或商品时不混入迟到结果。沿用批准的响应式与基本无障碍要求，可购买状态为当前快照而非库存保证。

#### Scenario: 查询导航与评论隔离
- **WHEN** 快速切换查询、筛选后换页或前后退，以及从商品 A 切换到 B 读取评论
- **THEN** URL 与所示结果一致，筛选变化归零分页，旧请求不覆盖新结果，A 评论不追加到 B

#### Scenario: 页面基本可用性
- **WHEN** 在桌面或移动宽度通过键盘浏览列表和详情
- **THEN** 核心内容与状态可读，控件有标签和可见焦点，错误与空结果可区分且可重试

### Requirement: HTTP 与真实 MCP 共享只读语义

系统 SHALL 通过 HTTP 和 Nest MCP 的 search_products、get_product、list_product_reviews 共享查询用例、校验与公开投影；协议包装不同不改变业务结果或错误含义。MCP MUST 校验服务身份及适用 Host/Origin，拒绝越权或非法请求。S1 验收包含真实 Codex 连接及三个工具调用，不能以模拟客户端替代。

#### Scenario: 跨入口一致
- **WHEN** 同一目录/库存下对两个入口发送相同正常及异常查询
- **THEN** 数据、分页、字段过滤与业务错误语义一致，均无交易副作用

#### Scenario: 真实 Host 与拒绝边界
- **WHEN** Codex 使用有效配置调用三个只读工具，或请求使用无效身份/不允许的 Host/Origin
- **THEN** 有效调用成功完成搜索、详情与评论读取；不允许请求被拒绝，记录真实运行结果而非伪造通过

### Requirement: 多目标独立有界查询
系统 SHALL 接受1～5个按输入顺序标识的搜索目标；目标ID唯一，每组保留独立文本、筛选、分页及状态。每组默认返回4项、最多10项，单次最多50个商品引用，不静默截断非法输入。单组排序仍先筛选再按原推荐分数降序、商品ID升序；搜索不写车、不预留、不生单。

#### Scenario: 两类商品及独立预算
- **WHEN** 同一请求搜索耳机最高2000元、水杯最高1000元
- **THEN** 返回两个同序目标，各自执行预算，不要求同一商品同时匹配两类，不用一组高分结果挤掉另一组名额

#### Scenario: 非法批量输入
- **WHEN** 目标为空、超过5个、ID重复、单组limit超过10、上下界倒置或包含未声明字段
- **THEN** 整个请求返回校验错误，不执行部分目标、不静默拆单或截断；每组q不超过200字符，标签不超过80字符

### Requirement: 简繁与受控跨语言文字匹配
系统 SHALL 对查询与可搜索商品字段使用同一确定性文字规范化，覆盖NFKC、大小写和简繁；对明确登记的中英文术语使用等价别名匹配。显示原始商品文案，不改原件或商品ID。别名不推断商品规格、不把上位概念和子类自动当同义词；未知术语保留原文字面查询，不自动翻译、纠错或删词扩大结果。

#### Scenario: 等价文字输入
- **WHEN** 在相同目录/库存下用「蓝牙」「藍牙」「Bluetooth」查询，且蓝牙词组已登记为同义概念
- **THEN** 候选集合及排序一致，原商品名仍保持原文；全角及大小写变体同样一致

#### Scenario: 短语与歧义保护
- **WHEN** 查询已登记的「water bottle／水瓶」或未知英文词，以及不等价的「耳机／头戴式耳机」
- **THEN** 前者按完整短语匹配，不让water一词单独扩大结果；未知词不被丢弃；后者不无条件互换，不凭搜索命中声称商品满足规格

#### Scenario: 硬约束与单查询一致
- **WHEN** 对单目标或批量目标同时使用别名文本、价格及品牌/分类筛选
- **THEN** 仅文字匹配采用等价扩展，筛选仍按声明值严格应用，不提高预算或放宽品牌/分类；各入口单目标候选语义一致

### Requirement: 分组引用与公开商品去重
批量响应 SHALL 返回有序groups及按唯一商品ID去重的products；成功组提供原目标、当前页productIds、匹配总数与nextOffset，无匹配为明确empty，组引用均能解析。跨组同商品可以各自引用，但同名不同ID不能合并；同一次响应中一个ID只有一份公开摘要。不得暴露推荐原分、毛利、凭证或原始内部数据。

#### Scenario: 重叠目标和同名商品
- **WHEN** 两目标都匹配P001，且P001/P002商品同名
- **THEN** P001在products只出现一次、两组均保留其引用，P002仍为独立商品；组内没有重复ID，数量不是购买数量

### Requirement: 分组分页版本与失败恢复
系统 SHALL 用目录版本及匹配规则版本校验批量续页，任何非首页请求须携带两个版本，每组分页只改变该组；条件改变时该组从第一页重新查询。库存每次读取当前值，不承诺跨请求快照或库存变化时的无遗漏分页。无匹配、局部技术失败、全局依赖失败须区别；可独立识别的单组失败保留其他成功组，共享目录/库存读取失败则整个请求技术失败，不返回伪造空结果。

#### Scenario: 原卡片分组翻页
- **WHEN** 用户翻耳机组下一页，水杯组未变化且版本仍有效
- **THEN** 只替换耳机组当前页，保留水杯组及顺序，不生成新展示卡片；过滤可购的库存变化可使页边界变化，明确支持从首重新查询

#### Scenario: 目录或匹配规则更新
- **WHEN** 续页携带旧目录版本或旧匹配规则版本
- **THEN** 拒绝拼接，提示重新查询完整集合，不把旧组结果当成当前版本结果

#### Scenario: 空组及技术失败
- **WHEN** A有结果而B无匹配，或B发生可独立识别的可重试错误，或共享库存依赖失败
- **THEN** 分别展示A和明确empty的B、A和明确error的B、或整个请求技术错误；不省略B，不用缓存库存或零库存冒充当前事实

### Requirement: 批量查询入口一致与单目标兼容
系统 SHALL 在只读HTTP及MCP批量查询间保持同一数据、筛选、排序及错误语义；合法旧单目标输入继续返回原Page形状，新增批量结果由显式kind区分。单目标也采用新文字匹配规则。所有读入口保留认证及适用Origin/Host/输入边界，不引入服务端搜索会话或交易副作用。

#### Scenario: 新旧调用并存
- **WHEN** 旧客户端传q，或新客户端传queries，或同时传两种模式
- **THEN** 前两者分别获得原Page和grouped结果，后者被拒绝；无Apps的Host仍得到全部组状态及可读摘要

### Requirement: 共享有界分类发现

系统 SHALL 从当前目录全部商品提取非空分类，按原值去重和确定性升序返回 `value`、`label`，两者均为原分类文本；值可直接用于既有精确分类筛选。分类独立于文本查询、预算与库存，不声明存在可购商品。查询 SHALL 支持 offset（默认0）、limit（默认50、最大100）和 catalogRevision；返回 items、total、nextOffset、catalogRevision，续页必须携带匹配版本。非法输入和技术故障必须明确失败，不伪装为空目录。

#### Scenario: 分类完整性与稳定分页
- **WHEN** 同一目录含重复分类、不同简繁写法、空分类以及仅含售罄商品的分类，调用者连续读取所有分页
- **THEN** 非空分类按原值各返回一次，简繁不同原值不合并，售罄分类保留；分页稳定且无遗漏或重复，不返回商品、库存、推荐分数或毛利

#### Scenario: 非法输入及目录变化
- **WHEN** offset为负数、limit超过100、输入含未知字段、续页未带版本或版本已经变化
- **THEN** 非法输入返回校验错误，版本过期返回CATALOG_CHANGED，不静默截断或混合分页

#### Scenario: 空目录与服务故障
- **WHEN** 目录有效但没有非空分类，或目录读取发生技术故障
- **THEN** 前者返回空items、total为0及nextOffset为null，后者返回明确技术失败；库存依赖不可用不影响纯目录分类查询

### Requirement: MCP 分类探索入口

系统 SHALL 通过只读 HTTP 与 MCP `list_product_categories` 提供相同分类查询、验证及公开字段。MCP 工具 SHALL 无 UI、无交易副作用，并保留既有服务身份及适用 Host/Origin 校验。工具说明 SHALL 指引调用方在分类不明确时按需探索，明确需求可直接搜索；分类是查询线索，不是规格或适用性保证，最终搜索展示继续遵循既有单卡片约束。

#### Scenario: 跨入口及调用边界
- **WHEN** HTTP与获授权MCP读取同一页，或MCP使用非法身份与不允许的Host/Origin
- **THEN** 前者返回同一分类内容及分页语义，后者拒绝访问；有效调用不建车、不预留、不生单、不产生Apps卡片

#### Scenario: 模糊意图与明确查询
- **WHEN** Agent不知道分类名称，或已经掌握用户明确查询条件
- **THEN** 工具描述分别支持先探索再查询、直接查询的路径，不要求所有搜索先调用分类工具；商品具体能力仍须详情核验，不自动放宽预算等硬约束

### Requirement: Web 分类选择与恢复

普通 Web SHALL 使用真实分类选项的单选下拉框替代手输分类，提供“全部分类”；Apps仍不显示搜索表单。选项采用共享分类发现结果，支持按需加载后续分类并明确列表未加载完。提交有效选项使用其原value，选择全部时移除category；改变筛选从商品第一页开始。URL恢复和前后退须显示原条件，失效或尚未获取的值不得静默改为全部。分类加载失败须明确展示和提供重试，保留其他搜索能力及当前条件。

#### Scenario: 选择与清除分类
- **WHEN** 用户用键盘选择分类、提交，再选择全部分类提交
- **THEN** 搜索依次使用该精确分类值、无category；每次重置offset和旧分页版本，其他仍填写的搜索约束保留；控件有标签和可见焦点

#### Scenario: URL中的未列出分类
- **WHEN** URL带有不在当前选项页中的分类，或目录更新后该值不再存在
- **THEN** 页面保留并显示该值为“当前条件（未在已加载分类中）”，不冒称已确认失效；用户可保留条件搜索或显式切换，查询结果仍按原精确筛选语义处理

#### Scenario: 加载失败与追加分页
- **WHEN** 分类首次读取或后续页失败，或读取下一页时发现目录版本变化
- **THEN** 页面提示错误并允许重试，不清空当前条件或伪造全部分类；版本变化时重新获取分类第一页，不拼接旧页；未读取完时提供明确的加载更多入口
