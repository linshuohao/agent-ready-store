# webmcp-shopping Specification

## Purpose

让浏览器 Agent 通过商城主动注册的页面工具完成商品发现和购物车准备，取得与当前页面一致的权威报价及 AI 优惠；明确生命周期、并发与降级边界，购买由Human在网页审阅并点击支付，经受保护UI直接成单且原地恢复，无需Agent后续提交。

## Requirements

### Requirement: 页面工具与独立验收

系统 SHALL 按当前页面提供结构化搜索、商品详情/评论、加购和当前车读取/编辑工具，商品查询与创建沿用现有契约；购物车页 update_cart 接收预期版本与一个加购、设量或移除操作，不再接收整车 items；返回完整服务端车和报价。基础MCP原七工具保持兼容，新增工具见agent-shopping。页面工具还须覆盖当前车结算准备、确认等待/状态查询；这些工具不批准购买。不注册确认购买、提交订单或模拟点击工具。真实浏览器/Host 的发现、调用、页面反馈及购物准备闭环 MUST 独立验证，不以模拟调用或基础 MCP 成功代替。

#### Scenario: Agent 准备购物
- **WHEN** 支持所选 WebMCP API 的真实 Host 调用当前页面工具搜索、查看商品、加购并编辑
- **THEN** 返回有界公开商品信息或权威车快照与完整报价，页面同步展示结果；进入Agent模式Checkout只读恢复原准备及完整摘要，Human明确点击支付后网页直接下单；不自动调用普通review撤销原准备，不要求Agent接续

### Requirement: Agent 优惠及普通车接手

系统 SHALL 将 WebMCP 工具成功创建的非空有效车记为 AGENT；有合法车权限时，成功工具编辑普通车 SHALL 在同一原子更新中转换为 AGENT，递增版本并应用既有 AI 优惠。无需额外 Agent 身份认证；客户端不得通过普通建车参数任意指定来源。只读查询、工具注册或失败操作 MUST 不转换来源。

#### Scenario: 新车及同车转换
- **WHEN** 工具首次有效加购，或携有效车权限和正确版本成功保存 HUMAN 车
- **THEN** 新车或原车成为 AGENT，返回服务端折扣报价；转换保留 cartId、访问能力、创建时间和有效期，不建替代车、不扣库存

#### Scenario: 转换失败与只读
- **WHEN** 仅读取 HUMAN 车，或编辑发生过期、无权限、条目非法、版本冲突或事务失败
- **THEN** 不因该次调用转换来源；失败不保存部分内容或优惠状态，客户端提示重新加载服务端数据

#### Scenario: 后续 Human 编辑与完成车
- **WHEN** Human 后续编辑 AGENT 车，或工具尝试修改已完成车
- **THEN** 前者保留 AGENT 来源；后者拒绝，原订单金额与来源快照不变

#### Scenario: 旧确认与并发提交
- **WHEN** WebMCP 来源转换与持旧确认的订单提交竞争
- **THEN** 转换先提交则旧版本购买失败并要求重新审阅和新点击；订单先提交则转换拒绝，不发生按旧确认购买新报价

### Requirement: 生命周期与同页协调

系统 MUST 只注册当前有效页面能力，离页/卸载后撤销，旧响应不得导航或更新新车。服务端是购物车权威来源；客户端 SHALL 不逐项协调、比较或合并本地草稿与远程版本，不保存或重放待恢复编辑。创建幂等与购买恢复保持。

#### Scenario: 脏草稿和工具写入
- **WHEN** 页面有未保存草稿，工具尝试修改当前车
- **THEN** 明确拒绝；Human 与工具共用同车短暂写入保护，在途时返回忙碌、不排队，Human 数量输入暂时禁用，不能被工具结果覆盖；请求结束释放短暂保护

#### Scenario: 编辑冲突或响应未知
- **WHEN** Web 或 WebMCP 编辑被服务端拒绝版本，或响应丢失
- **THEN** 明确返回冲突/未知，提示显式重新读取服务端数据；此前在途成功不能清除此要求。不自动读取比较、不重放、不长期锁住全局写入，用户重新加载后按最新版本调整

#### Scenario: 创建结果未知
- **WHEN** 工具创建响应丢失且原材料仍在
- **THEN** 仅 retry_cart_creation 可显式沿用原通道、请求键、证明与条目恢复原车；不接受编辑恢复，不重复建车

#### Scenario: 离页结果隔离
- **WHEN** A 车工具请求未返回即切到 B
- **THEN** A 结果不影响 B，不更新 B 的快照或导航

### Requirement: 权限、降级及创建统计

系统 MUST 保留同源防护、车级凭证、统一期限和服务端计价，浏览器不得取得 MCP 服务秘密。WebMCP 不可用时普通 Web 可操作并明确能力限制，不能冒充模式验收完成。有效 Agent 创建统计继续仅计 Agent 流程首次成功创建的有效车；HUMAN 车后续转为 AGENT 不补计创建。

#### Scenario: 不支持及越权
- **WHEN** 浏览器无 WebMCP 能力，或调用者无目标车合法权限
- **THEN** 前者保留普通购物并说明工具不可用；后者拒绝访问或转换，不泄露车快照或秘密

#### Scenario: 创建与接手分开
- **WHEN** 工具新建有效 AGENT 车并重试，或接手已有 HUMAN 车后编辑、到期或成交
- **THEN** 前者有效创建仅计一次；后者不新增 Agent 创建计数，已记录创建事实不因后续生命周期撤销

### Requirement: 操作契约发现与干净快照刷新

系统 MUST 使 Human 与页面工具共享同车操作入口、状态和报价。工具描述与 schema SHALL 清楚区分增量加购、绝对设量、移除和创建重试，拒绝旧 items 及来源/价格等越权字段；不得将基础 MCP 的同名工具参数误用于 WebMCP。页面返回时按 shopping-cart 的草稿/忙碌规则校准，读取不升级来源。

#### Scenario: 工具接手与重发现
- **WHEN** Host 重新发现当前车页 update_cart 后携当前版本提交一个设量或移除操作
- **THEN** 成功原子升级来源并同步完整报价，失败不升级；旧整车 items 参数明确拒绝，Host 必须采用当前发现契约，不缓存旧工具句柄

#### Scenario: 工具与 Human 同车写入
- **WHEN** 工具请求进行中 Human 尝试改量，或 Human 请求进行中工具尝试写入
- **THEN** 当前浏览器同车短暂互斥，不自动排队、合并、重放；其他设备及基础 MCP 的写入仍由服务端版本裁决

### Requirement: 准备会话与网页直接支付

WebMCP SHALL 在无审阅副作用的浏览器会话初始化后准备结算；同源导航、刷新与重注册保持scope，确认页只读恢复。Human支付由网页受保护请求直接完成，MUST 不注册模型可调用的支付工具，不将消息投递或Agent活跃作为成单条件。具体内容绑定、取消、重试及权限沿agent-purchase-authorization。

#### Scenario: 准备后离页与支付
- **WHEN** Agent准备完成后进入确认页，或Agent已结束当前轮次
- **THEN** 撤销旧页工具并重新发现，只读恢复同review摘要；Human点击才直接成单，原地展示订单，未点击零订单/零扣库存

#### Scenario: 会话丢失及响应未知
- **WHEN** Cookie缺失/替换，或支付丢响应后刷新
- **THEN** 前者不凭reviewId接管准备，后者有原权限时只读核实原结果；不自动支付或准备、不由Agent补发submit，一次无订单不证明旧请求失败
