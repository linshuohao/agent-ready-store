# Design

## Context
复用 agent-shopping 与 mcp-app-shopping 正式 Spec，以及 REQUIREMENTS CART-06/ORDER-01、D-21 模拟交易边界。2026-10-31 Human 已要求按前轮建议作小范围修订，授权实现与局部验证；未授权提交、发布或归档。

## Goals / Non-Goals
使模型目录表达最终意图优先级，公开失败可恢复原因。保持现有工具、整行选购、服务端预算判定及幂等行为。

## Decisions
- 修订现有工具说明，不增加通用意图状态机或编排服务。购买中的查询是内部步骤，只有独立搜索意图展示搜索卡。
- MCP envelope 增加环境标记及错误恢复指引；公开金额/规格差异由原校验点返回，不暴露内部异常。不改变 retryable 的原样重试语义。
- 分类/品牌保持精确匹配并在 schema 注释中说明；规格保持原文相等断言，只传用户明确硬约束。
- 已有同 SKU 与本次数量冲突时解释整行限制并澄清，不自动改旧数量、换车或购买整行。

## Risks / Trade-offs
工具描述不能强制模型遵循 → 自动化核对协议与错误内容，真实 Host 卡片数和模型路由另行验收。共享错误新增字段是兼容性增量，消费者允许这些字段但不改变失败判定。

## Migration Plan
无需数据迁移；部署后刷新 Host 工具发现缓存。撤回本次源码即可回滚。

## Review
聚焦设计自查：范围沿用用户已授权建议，无交易不变量变化；明确失败与未知结果分别处理，不以支付作为遗漏约束兜底。

## 每轮单卡补充（Human 追加要求）
以每轮至多一次search_products/create_order展示为目标，咨询可零卡。预算/规格优先无UI quote_selection预检以减少可预见失败；展示失败或未知后本轮不再开卡，保留原请求后续恢复。静态工具元数据不能撤回Host已创建的失败卡片，也不能保证Host不重投递，不能宣称服务端硬性保证可见卡片数。未修改同键恢复服务；后续轮次仍按原规则恢复。

## 后续授权
2026-10-31 Human明确授权提交本次修订并更新本地MCP供实际单卡测试；不扩展到Push/Merge、公网发布或Change归档。
