## MODIFIED Requirements

### Requirement: Apps资源与公开展示
系统 SHALL 仅提供当前版本的可发现隔离静态UI资源并关联实际步骤工具结果，不提供历史 URI 别名、重定向或版本回退；静态资源无交易数据、运行时凭证或私有商品字段。动态视图展示服务端公开商品、车版本/条目/预估及订单固定快照，不执行商品评论脚本或指令，不客户端计算优惠。不支持Apps的Host可使用新基础MCP，不承诺旧七工具schema兼容。 MCP Demo仅按agent-shopping的「Demo入口模式」免除Token认证，其他边界不变。

#### Scenario: 资源加载和公开数据
- **WHEN** Host读取合法资源、未知资源或显式token认证模式下无有效服务认证请求资源
- **THEN** 分别返回静态视图、明确错误或拒绝，不读取任意文件；商品同名不合并，问题条目可见，已有订单不使车只读

#### Scenario: 内嵌搜索结果与垂直区块布局
- **WHEN** MCP Apps展示搜索结果、商品详情、购物车或订单等内嵌页面
- **THEN** 目录直接展示搜索结果，不渲染搜索或筛选表单；内嵌页面各主要区块纵向排列，不采用左右分区；搜索商品卡片可按可用宽度并排，窄视图自动减少列数，图片保持紧凑高度而不随整行宽度放大；普通Web保持现有搜索和响应式布局，继续使用同一共享应用

#### Scenario: 按意图只展示最终结果
- **WHEN** 用户明确购买，或只要求搜索商品
- **THEN** 购买准备使用无UI的query_products及详情/购物车/报价工具，同一次购买完整集合只调用一次create_order生成包含全部商品的一张最终结算卡片（Human明确拆单除外）；搜索使用search_products生成一张搜索结果卡片；支付与状态恢复在原结算卡片更新，不生成中间工具卡片、不自动外跳

#### Scenario: Host缓存最终卡片旧URI
- **WHEN** Host读取此前公布但已非当前版本的资源URI
- **THEN** 返回资源不存在错误，不映射至当前HTML；Host须刷新工具和资源发现后使用当前URI，不能重放购买写请求来修复资源加载

### Requirement: 批量结果协议兼容与真实Host证据
Apps SHALL 明确校验单目标Page和批量grouped两种结果，未知kind或引用缺失不能被当成空成功。当前资源继续支持合法单目标与批量结果；这不构成对历史资源URI的支持。验收分别记录数据工具无UI、一次展示调用、实际卡片数量及Host版本；不支持Apps时保留分组文本/结构化结果，不称为Apps展示通过。

#### Scenario: 新旧资源切换
- **WHEN** Host缓存旧工具目录或旧卡片结果，或刷新后调用批量展示
- **THEN** 旧URI明确失败并要求刷新发现；当前资源支持合法单目标和批量结果，能力不足有明确提示，不丢组、不把解析失败降级成无匹配

#### Scenario: 真实多目标搜索
- **WHEN** 在目标真实Host执行包含简繁/英文术语的两个目标，并进行组内分页和详情返回
- **THEN** 记录完整目标、调用轨迹、一张实际卡片及分组恢复结果；SDK替身通过不能代替Human确认，模型多次展示产生多卡必须记为失败或明确未解决限制
