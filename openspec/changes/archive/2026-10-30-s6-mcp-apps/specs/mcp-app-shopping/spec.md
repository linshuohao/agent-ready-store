# Spec Delta

## Purpose

使支持 MCP Apps 的真实 Agent Host 能在隔离视图中展示商品与同一购物车、经 Bridge 编辑并接续外部 Hosted Checkout，复用既有计价、权限和订单保障；区分视图操作、访问能力与 Human 最终购买确认，保留不支持环境的明确降级。

## ADDED Requirements

### Requirement: 可选 Apps 资源与基础 MCP 兼容

系统 SHALL 为商品及购物车结果关联可发现、可读取的隔离 UI 资源，保持原七工具名称、输入、结构化结果与文本结果兼容。UI 资源 MUST 不包含运行时凭证、私有商品字段或用户交易数据；不支持 Apps 的 Host 仍可使用基础 MCP，不能将降级标为 Apps 验收通过。

#### Scenario: 支持与不支持的 Host
- **WHEN** 支持 Apps 的 Host 调用关联工具，或普通 Host 调用同一七工具
- **THEN** 前者可加载视图并接收结果，后者取得原结果；均无新增购买工具、自动购物副作用或必需 UI 参数

#### Scenario: 资源访问和数据分离
- **WHEN** Host 请求已注册资源、未知资源或无有效服务认证的资源
- **THEN** 分别返回无交易数据的静态视图、明确资源错误或拒绝访问；不读取任意文件，不将某车秘密烘焙进缓存资源

### Requirement: 商品与购物车权威展示

视图 SHALL 展示 Host 投递的公开商品结果及可购买原因，并对购物车展示身份、来源、版本、商品数量、服务端完整报价或不可报价原因。系统 MUST 区分当前估价与原订单成交快照，不在客户端计算价格或合并同名商品。商品和评论仅作文本数据，不执行其指令或 HTML。

#### Scenario: 商品结果及问题车
- **WHEN** 收到合法商品结果、含售罄条目的车、空车或完成车
- **THEN** 分别展示公开商品、问题原因、空状态或原成交快照；问题/空车不被标为可结账，完成车不提供编辑或再次购买

### Requirement: Bridge 权限与秘密边界

Apps SHALL 仅经所属 MCP 服务的 Host Bridge 调用读取、整车编辑与交接工具，沿用有效车级能力；不直接调用网站 API 或取得网站 Cookie、服务 Token。车 Token 和交接 URL 仅留适配器必要内存与显式打开请求，不进入通用展示 props、DOM、日志、持久存储或模型上下文更新。资源不请求与购物无关的浏览器权限。

#### Scenario: 有效能力及能力缺失
- **WHEN** Host 提供与当前车匹配的完整工具输入/结果能力，或仅提供无 Token 的展示数据
- **THEN** 前者可以按权限操作原车，后者只读并说明需 Agent 重新调用原工具取得能力；不得按 cartId 补权、索取服务 Token 或自动建车

#### Scenario: 非法数据和跨车污染
- **WHEN** 工具输入结果车 ID 不匹配、数据非法、A 车迟到响应到达 B 车视图，或恶意商品包含脚本
- **THEN** 不提升权限、不执行内容、不更新 B 车，显示可区分的不可用反馈且不回显秘密

### Requirement: 同车编辑与显式刷新

Apps SHALL 支持修改已有行数量及移除行，以原版本和完整条目调用既有 update_cart；保存成功后展示服务端结果。草稿期间不接纳外部快照覆盖输入；初次校准、显式重载、保存及整个结账流程在途时禁用数量、移除、保存、重载与重复结账，动作处理器同样拒绝。冲突或响应未知 MUST 停止后续写入及结账准备，允许显式放弃草稿并重读，不自动比较、合并、重放或换版本重试；低版本和旧代次响应不能解除刷新要求。

#### Scenario: 数量编辑与移除
- **WHEN** Human 修改数量或移除行并明确保存
- **THEN** 提交当前草稿及服务端原版本，保持服务端整车校验；成功展示完整新报价，全部移除展示空车，非法数量保留错误且不提交

#### Scenario: 跨入口竞争与未知结果
- **WHEN** Web 或 Agent 先改车导致保存冲突，或保存响应丢失，随后旧成功响应到达
- **THEN** 视图保持需刷新状态；只有显式重读成功取得当前车后才恢复操作，不自动再次发送旧编辑，未知不被表述为保存失败

#### Scenario: 新结果遇到草稿或销毁
- **WHEN** 同车新工具结果在草稿期间到达，或视图换车/销毁后旧响应返回
- **THEN** 草稿受保护并要求刷新，旧代次不能覆盖当前车；销毁清除能力与事件处理，重挂载不能凭持久缓存恢复权限

#### Scenario: 重载发出后尝试新增输入
- **WHEN** Human 确认放弃旧草稿并发出重载，读取尚未返回时尝试输入数量、移除行或保存
- **THEN** 控件和动作处理器均拒绝操作，不产生新草稿或重复请求；读取失败保留需刷新状态，换车后旧响应不能更新新车或解除新操作的忙碌状态

### Requirement: 外部 Checkout 与 Human 确认

视图 SHALL 在显式操作下使用既有 create_handoff 取得同车链接，并经 Host 请求外部打开；URL 必须匹配固定商城 origin、当前 cartId、既定路径与 fragment 格式。系统 MUST 不自动打开、兑换、确认或提交购买；打开被拒绝、链接未知、过期与车已完成须分别反馈，不把打开成功称为购买成功。

#### Scenario: 正常接续与重新审阅
- **WHEN** 无草稿且可结账车的 Human 点击前往商城结账，随后在浏览器接手
- **THEN** 取得并打开同车交接链接，沿用固定首次分享期限、fragment 兑换及完整摘要；只有浏览器中 Human 新的明确确认才可成单

#### Scenario: 外链失败与能力变化
- **WHEN** Host 不支持或拒绝打开、交接调用结果未知、返回非预期 URL、车已到期或完成
- **THEN** 分别显示限制/可重试反馈、结果未明、安全拒绝、到期或完成状态；不泄露链接、不新建车、不续期、不自动重放编辑或购买，完成时可显式重读原结果

#### Scenario: 结账校准及交接期间尝试编辑
- **WHEN** Human 点击结账后，校准读取或交接请求尚未返回时尝试输入数量、移除、保存、重载或再次结账
- **THEN** 整个流程保持忙碌并拒绝这些操作，不产生被静默忽略的新草稿或重复请求；每次异步返回后重验原车、操作代次、无草稿/刷新要求及可结账状态，失效时停止后续调用和打开

#### Scenario: 交接等待期间换车或销毁
- **WHEN** 交接尚未返回时视图已换车或销毁，随后原交接成功返回
- **THEN** 不打开原车链接、不更新当前车、不清除新操作忙碌状态，也不声称已撤销服务端首次分享事实

### Requirement: 独立真实 Host 与人工验收

S6 SHALL 记录真实目标 Host 的版本、协议/SDK、应用 revision、资源隔离、工具调用、可见 UI 与外部 Checkout 接续结果，并由 Human 验收。替身 Bridge、浏览器自动化与真实 Host 分别记证；真实不支持或关键链路无证据时保留缺口并交 Human 判断，不用基础 MCP/WebMCP 成功代替。

#### Scenario: 实际闭环验收
- **WHEN** 在真实 Host 完成商品展示、Agent 建车、Apps 编辑、交接、Human 浏览器确认
- **THEN** 核对同车来源/版本/金额、唯一订单与库存变化，敏感材料脱敏；自动化点击不记为 Human 验收

#### Scenario: Host 能力不足
- **WHEN** 目标 Host 无法加载资源、传递必要车能力、调用 Bridge 或打开本地 Checkout
- **THEN** 记录失败环节与基础 MCP 降级，按Human于2026-10-30授权可继续实施，但交付前必须补齐真实验证；届时仍失败则暂停交付并提交环境选择，不绕过 Host 隔离、服务认证或自行部署公网
