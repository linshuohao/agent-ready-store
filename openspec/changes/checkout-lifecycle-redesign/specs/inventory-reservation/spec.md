# Spec Delta

## Purpose

使待支付订单在固定十五分钟内持有可追溯的整单库存预留，统一公开可售量、支付消费及关闭释放的事实，避免并发超卖、重复扣减和过期复活；保留故障后可恢复、可核对的订单与库存关系。

## ADDED Requirements

### Requirement: 订单预留与可售量
系统 SHALL 在创建待支付订单时原子预留全部所选数量。正常商品满足 `0 <= reservedQuantity <= quantity`，可售量为实际剩余量减未消费或未物化释放的预留量；预留归属于订单明细及其状态。加购和报价不占库存，异常库存不得被修饰为可购买。

#### Scenario: 竞争最后库存
- **WHEN** 多车并发购买同一商品且总需求超过可售量
- **THEN** 成功预留不超过可售量，失败请求不产生订单、部分预留或车行转出

#### Scenario: 已有预留与新加购
- **WHEN** 订单持有有效预留使公开可售量为零，用户支付原单或重新购买同SKU
- **THEN** 原单使用自己的预留；新购买不得复用该预留，未释放占用始终计入同一可售口径

### Requirement: 固定期限与到期准入
系统 MUST 将截止固定为锁等待和校验完成后的服务端成功创建时刻加15分钟，重读、重试、分享与重挂载不续期。支付在取得订单及库存所需锁后以数据库当前时间准入，达到截止等号即禁止新支付；截止前准入的短事务可以完成提交。

#### Scenario: 等锁跨截止
- **WHEN** 支付在截止前到达但取得全部所需锁时已经到期
- **THEN** 拒绝支付，不扣实际库存；本地时钟和请求到达时间不能放行

#### Scenario: 准入后跨截止提交
- **WHEN** 支付截止前完成锁后准入，提交时已超过截止
- **THEN** 允许提交PAID，释放任务不得释放该单已经消费的数量

### Requirement: 消费释放与终态一致
系统 SHALL 将支付、取消和到期关闭与库存变动原子提交。支付同时减少实际量和预留量；关闭仅释放预留，不回车。既有PAID或关闭事实不改写；未关闭单锁后已到期记EXPIRED，未到期才按原因记CANCELLED。

#### Scenario: 支付取消到期竞争
- **WHEN** 同单支付、取消和多个释放执行者并发，或成功后重复调用
- **THEN** 仅一次终态及一次消费或释放，PAID无关闭事实，重复取消不改关闭原因，不退款、不复活

#### Scenario: 事务中途故障
- **WHEN** 消费或释放过程在写入订单状态前后失败
- **THEN** 本次库存和状态一起回滚，原订单、快照与尚有效预留仍可恢复

### Requirement: 到期补扫与释放目标
系统 SHALL 在服务启动后补扫到期订单并持续释放；默认每秒扫描，在正常服务、数据库和设计负载下目标截止后5秒内物化释放。故障期间不承诺该上限；未释放占用保守计入库存，始终禁止过期新支付。系统 MUST 提供积压、最老超时及账实核对证据。

#### Scenario: 停机后恢复及多实例
- **WHEN** 服务停机跨截止后重启，或多个实例同时处理积压
- **THEN** 补扫后归属账本与计数一致，不重复释放；记录设计负载、实际释放时延和故障恢复结果，不能以单元测试替代性能验收
