# Spec Delta

## MODIFIED Requirements

### Requirement: 有效创建事实及去重

系统 SHALL 仅将可信 Agent 流程成功创建、初始非空且商品/数量均有效的 Cart 计作有效创建，按 Cart ID 一车一次。普通 HUMAN 车、失败或回滚创建不计入。系统 MUST 保留该创建事实，不因后续编辑为空、售罄、关联订单过期或支付、响应丢失或重启撤销，也不因重试/读取/分享新增次数。

#### Scenario: 创建后生命周期变化
- **WHEN** 成功 Agent 建车随后修改、删空、分享、到期或成交，并多次重试原创建
- **THEN** 有效创建总数仅增加一次，建车不预留库存；独立生单才预留，支付才扣实际量，关闭释放预留

#### Scenario: 非有效创建
- **WHEN** 普通 Web 建车、Agent 空车/非法创建、事务回滚或同键异内容冲突
- **THEN** 不增加有效 Agent 创建数；不同 ID 的合法 Agent 新车各计一次，不声称识别重复意图

## ADDED Requirements

### Requirement: 订单生命周期计量
系统 SHALL 按已提交订单事实区分创建数、有效待支付数量、关闭数量和PAID数量；购买成功及收入仅来自PAID及固定金额。AI生单不补计Agent建车，读取、重试或预留不计成交；沿用本地受控只读统计，不新增公开指标服务。切换清理旧流程数据不做历史回填，不宣称累计运营达标。

#### Scenario: 一车多单及重复读取
- **WHEN** 同一车创建多笔订单，部分支付、部分关闭，其余待支付，并重复读取和重试
- **THEN** 创建按orderId去重，成功/收入仅统计PAID一次；Agent车创建事实仍最多一次，普通车上AI订单不补记Agent建车

#### Scenario: 过期尚未物化
- **WHEN** CHECKOUT已经过截止但closedAt仍为空
- **THEN** 不计有效待支付或PAID，不谎称关闭已提交；统计明确该派生到期与物化关闭差异
