# Spec Delta

## Purpose

让顾客把商品选择保存为可恢复、可编辑且受车级权限保护的购物车，避免建车重试和并发编辑破坏购买意图，并为后续独立确认及订单流程提供一致输入。

本文为Approved S2增量规格，Human于2026-10-29明确批准本规划并授权实施，来源见Proposal。L-01、恢复限制和S2/S4分期沿用已确认决定；运行行为仍待验证。

## ADDED Requirements

### Requirement: 创建与数量校验

系统 SHALL 按唯一商品 ID 和正整数数量创建普通购物车，数量不得超过当次运行库存；拒绝未知、不可购买商品及重复 ID，不能按名称合并、静默减量或部分接受。普通 Web 可创建空车。创建与编辑 MUST 不预留或扣减库存。

#### Scenario: 有效创建与非法输入
- **WHEN** 普通 Web 提交有效条目、空条目或包含无效数量/重复 ID/不可购买商品的条目
- **THEN** 有效整车或空车创建成功；非法整车被明确拒绝且不留下部分 Cart，库存始终不变

### Requirement: 持久编辑与冲突

系统 SHALL 读取持久化购物车并按调用者提供的预期版本整车替换条目；成功编辑原子递增版本并保留来源，旧版本编辑明确冲突。已有条目因库存减少或商品失效而受阻时 MUST 保留内容供调整；编辑可以删除问题条目，不能自动覆盖其他修改。

#### Scenario: 同车并发编辑
- **WHEN** 两个请求使用同一预期版本提交不同条目
- **THEN** 最多一个成功，另一个得到版本冲突；最终条目与成功版本一致，无丢失更新

#### Scenario: 库存下降与删除问题条目
- **WHEN** 已有数量超出当前库存，或某商品已失效，顾客读取并提交删除/改量后的有效整车
- **THEN** 读取保留原条目并说明问题；有效调整可以保存，无效调整整笔拒绝且原车不变

### Requirement: 创建幂等与恢复

系统 SHALL 将创建请求绑定到有效创建证明、请求键和原始条目；同证明、同键、同内容重试只创建同一车，返回当前车及相同访问能力，不重放原条目覆盖后续编辑。已有请求恢复 MUST 不以原条目仍满足当前建车条件为前提；库存或目录变化通过当前车的问题反馈，访问权限仍须有效。异内容或无有效证明 MUST 拒绝。服务重启及响应丢失不能破坏持久幂等。

#### Scenario: 响应丢失及编辑后重放
- **WHEN** 建车已提交但响应丢失，服务重启后持原证明重试，或该车编辑后再重试原请求
- **THEN** 仅有一个 Cart，恢复原访问能力及当前内容，后续编辑不被还原

#### Scenario: 不同请求或伪造恢复
- **WHEN** 同键异内容重试、并发提交同一请求，或只凭 cartId/requestId 请求恢复
- **THEN** 异内容和无证明恢复被拒绝；同请求并发最终仅一车，秘密不能被其他调用者领取

#### Scenario: 创建成功后购买条件变化
- **WHEN** 建车成功但响应丢失，原商品随后库存不足、售罄或从目录失效，服务重启后持有效原证明和相同请求重试
- **THEN** 恢复同一车的访问能力和当前内容，按当前商品/库存返回问题与报价，不因原商品已不满足新建条件而拒绝恢复，不创建新车且不改变库存

### Requirement: 车级访问与可信来源

系统 MUST 在读取和编辑时验证目标车能力；公共 cartId、另一车凭证及 MCP 服务凭证单独出现均不授予访问权。普通 HTTP 创建来源固定 HUMAN，拒绝客户端 origin/source/价格等越权字段；来源不因编辑改变。写请求须通过同源与请求伪造防护。秘密不得进入 URL query、公开响应、日志或持久客户端缓存。

#### Scenario: 错车与来源伪造
- **WHEN** 使用 A 车凭证访问 B 车，或普通创建请求伪造 AGENT 来源/商品价格
- **THEN** 访问或输入被拒绝，B 车不变且不能获得 AI 专属优惠

#### Scenario: 跨站与多车
- **WHEN** 跨站请求尝试写车，或同浏览器两个标签分别操作 A/B
- **THEN** 跨站写被拒绝，A/B 权限与内容互不覆盖；失败响应不泄露车内容或秘密

### Requirement: 固定访问期限

系统 SHALL 对未交接Human/Agent Cart采用服务端成功创建记录起固定24小时的访问期限；到期等号失效，读取、编辑、失败、重试及Cookie重设均不能续期或恢复过期权限。系统 MUST 不因访问失效删除Cart、修改库存或推导长期订单查询权。有效期内首次分享后统一改为首次分享起完整24小时，重复分享不续期；首次分享由后续S4实现。

#### Scenario: 创建期边界与重试
- **WHEN** 在创建截止前、截止等号或截止后读取、编辑或持原创建材料重试
- **THEN** 截止前按有效权限处理，截止等号及之后明确失效，不改原createdAt或补发新权限；Cart和Inventory内容不因期限校验改变

#### Scenario: 等待写锁期间到期
- **WHEN** 编辑请求到达时尚有效，但等待Cart写入锁后已达到创建截止时刻
- **THEN** 服务端以锁后当前时间拒绝编辑并保持原内容，不以请求到达时间或客户端计时放行

#### Scenario: 首次分享阶段切换的后续兼容
- **WHEN** 后续S4在创建截止前首次分享，或在创建截止等号及之后尝试首次分享
- **THEN** 前者保证首次分享起完整24小时，不被创建截止时间截短，后者拒绝；此场景为S4兼容约束，不能记录为S2已实现Handoff证据

### Requirement: Web 加购与购物车编辑

系统 SHALL 提供列表/详情轻量加购反馈和独立购物车页；加购不强制跳转。用户可修改数量、移除商品并看到当前报价、加载、空车、访问失效、保存失败和冲突状态。切换车或请求乱序时 MUST 不混入别车内容或覆盖脏草稿；S2 不提供可执行的最终购买动作。

#### Scenario: 加购与连续编辑
- **WHEN** 顾客加购、进入购物车、改量、删除至空车或遭遇保存失败/版本冲突
- **THEN** 加购结果明确可见，改量不静默修正，空车无可购买报价；失败保留草稿并提供明确重读/调整路径，冲突不自动重放覆盖

#### Scenario: 首次跨商品快速加购
- **WHEN** 尚无当前车，顾客点击商品 A 后在创建返回前尝试点击商品 B
- **THEN** 当前页面所有加购入口在同一创建期间均不可再次提交，第二次点击不被接受或显示成功；A 创建成功后恢复入口，顾客可将 B 加入同一车，不因两个入口分别建车

#### Scenario: 加购请求结果未明
- **WHEN** 创建响应丢失但当前页面仍持有创建材料，或已有车编辑响应丢失
- **THEN** 创建阶段保留统一进行中/结果未明状态并允许持原材料恢复，不生成新创建意图；编辑阶段保留原cartId、预期版本和完整条目并读取原车，读取旧版本时仍为结果未明，不恢复新编辑、不声称失败；允许用户显式重试同版本同条目，由版本条件保证原请求和重试最多一次成功

#### Scenario: 读取旧版本后原编辑提交
- **WHEN** PUT响应丢失，恢复GET读取原版本，随后原PUT与用户显式发起的同版本同条目重试竞争提交
- **THEN** 旧版本读取不能判定原请求失败，原请求与重试最多一个成功且版本仅递增一次；重试成功则确认保存，重试冲突则读取最新车，相同目标条目提示当前已符合原意图，不同条目显示冲突并保留原草稿供重新调整

#### Scenario: 恢复期间其他入口编辑
- **WHEN** PUT结果未明时，另一标签页先使版本递增，恢复读取的条目与原请求不同
- **THEN** 原预期版本的请求不能再覆盖新版本；界面展示当前结果及差异，不断言原请求从未成功，也不自动将原请求改为新版本重发

#### Scenario: 页面刷新与响应归属
- **WHEN** 创建成功后刷新原车，或 A 车请求迟于切换到 B 后返回
- **THEN** 有效 Cookie 可读取原车，A 响应不能覆盖 B；敏感响应不被共享缓存

#### Scenario: 响应前丢失创建材料
- **WHEN** 建车响应和 Cookie 均未送达，浏览器刷新导致原创建材料丢失
- **THEN** 明确显示创建结果无法确认，不凭公开ID补发权限或自动重建；Human已在本轮接受此恢复限制，长期恢复能力仍不在S2内

#### Scenario: 基本可访问性
- **WHEN** 在桌面/移动宽度以键盘编辑购物车
- **THEN** 输入有标签、错误关联输入、反馈可被辅助技术感知、焦点可见且保存失败后可继续操作
