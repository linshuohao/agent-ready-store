# Design

## Context

规划基线为本地 main 45797ad；2026-11-01 已从 3275e19 快进合入独立提案分支。新增分类发现、MCP结果引导及文档站均纳入本轮保护范围。动机与九项范围见 proposal.md。正式规格为行为依据；全局 Requirements/Product Design/Technical Design 未整体 Approved，不扩大历史批准。延续工程决策 T-08～T-11、T-11完整应用复用和MCP新协议增量；本地认证例外来自当前Human明确确认。

## Goals / Non-Goals

目标是全仓检查并完成有实际收益的升级与职责整理，公开业务语义保持不变。核心业务、集成、E2E场景及断言完整复用；内部方法单测按职责重写。仅本地免认证新增行为。无数据迁移、真实支付、公开部署免认证、视觉重做或动态插件平台。

## Decisions

### 1. 本地入口模式

新增 MCP_AUTH_MODE=token|demo，默认demo，显式token启用认证；非法值启动失败。token模式沿用24字符要求；demo不要求Token。保留Host/Origin、资源路径和输入校验，全部现有能力开放，Apps-only支付可见性不变。demo只用于本地部署：配置校验要求WEB_ORIGIN与允许Host为回环主机，在现有Vercel入口拒绝demo，不新增多云环境探测机制；容器内部监听0.0.0.0可以保留，但Compose发布端口仍绑定回环。不能只用NODE_ENV判断本地，因为本地生产构建也需演示。未配置模式时即使存在Token也保持demo。仅变量未定义使用默认值，空字符串、拼写错误与未知值拒绝启动。具体错误信息与解析集中在配置模块，不新建配置框架。

### 2. 工具逐个注册

优先使用McpServer.registerTool；必要时薄封装统一结果与维护钩子。每个定义包含名称、Schema、说明、注解、可见性和处理器；统一入口逐个注册，注册机制不识别商品/订单模块。文件可按维护需要分组，拒绝重复名称，不建中央switch或动态加载协议。

保留逐请求Server生命周期、choiceCodec校验、2026-07-28 input_required、旧协议、Apps旧URI、退役工具拒绝语义。适配SDK自动校验时保持现有错误封装；无法保持则先解决兼容，不擅改断言。复用新增result-guidance.ts，保留environment/recovery与constraintViolations；list_product_categories不依赖库存维护，不能被统一beforeToolCall误拦截。Apps构建与服务端资源版本抽取单一来源。

### 3. 全仓现代化与配置复用

逐工作区及独立site/检查依赖、废弃API及构建配置，依据实施时官方迁移说明确定候选版本，在本Change记录当前/目标/理由/兼容证据；不预先限制大版本，也不凭版本新旧盲目更新。site保留独立安装与锁文件，不为统一强行并入商城workspace。根目录ESLint提供可复用基础，Web叠加Next规则；TS公共项沿用tsconfig.base.json，Node和浏览器差异局部保留。统一适用的TS、Node类型及重复依赖声明，不新增配置包。语法迁移和依赖升级分批验证，不顺手改变公开契约。

### 4. 旧代码、职责与阅读性

追踪旧purchase-commands及页面、contracts、Provider的acquirePurchase/toolSave/retryTool调用链后删除不可达内部实现；保留公开退役入口410和有效转导出。cart.service先抽取纯视图映射、配置、校验，保留事务编排、锁顺序和幂等恢复顺序。Provider先清理退役接口，再分离反馈展示及状态协调，状态所有者保持唯一。改善命名、分段和多变量声明，注释解释不变量和原因，不逐行翻译代码。

### 5. 异常诊断

shared/result.ts未知异常通过现有日志能力记录requestId、操作名和经过筛选的错误信息，返回原错误形状。禁止记录Token、连接串、完整请求或原始商品数据；错误message/stack也必须避免携带秘密。调用链仅记录一次，不新增遥测服务；补关联与脱敏单测。

### 6. 文档源目录和发布路径

复用main新增的documentation-delivery-hub构建与兼容映射，不另建静态发布系统。design/delivery/presentation源文件分别收拢docs对应目录；与现有docs/presentation按职责合并，根README和AGENTS保持入口，openspec与references不移动。输出继续提供旧URL、资源路径及锚点，内部源链接同步更新。保持清单式分发，不复制references或秘密；迁移前核对原工作区delivery成果是否已合入，不能用旧副本覆盖新成果。

### Verification execution and comparison

实施前固定基线commit与环境、数据库fixture和现有核心用例清单；保存工具发现的名称、描述、Schema、注解、可见性，以及代表性成功/失败响应。重构后只归一化requestId、时间等非确定字段，不归一化金额、状态、错误码、约束详情、工具描述或恢复引导。除本地免认证外不得有未解释的契约差异。不存在的覆盖先补业务反例测试，不能仅靠新实现的方法单测证明等价。

在现有CI之外显式执行 `pnpm test:categories`、`pnpm docs:build`、`pnpm docs:check`、`pnpm docs:test`；site先使用自身锁文件冻结安装。根Vitest不包含site脚本测试，商城构建也不替代文档构建。CI命令的测试环境变量沿现有配置准备，确认测试确实执行而非条件跳过。日志故障不能遮蔽原业务错误。

真实并发覆盖同键同载荷、同键异载荷、两订单争库存、支付/取消/到期竞争；验证库存不负、预留不重复释放、终态不反转。前端覆盖原请求恢复和迟到响应。认证模式分别使用同一业务契约测试入口，不复制两套预期；补本地生产构建及Compose冒烟，不能只测开发模式。显式token认证保留完整既有负面测试。

测试提供有限场景内的回归证据，不能数学保证全业务不变。缺失真实Host或环境时标记未验证，不据此宣布验收完成；由Human决定剩余缺口是否可接受。

## Risks / Trade-offs

- SDK高层自动校验可能改变错误行为 → 契约比较及负面测试先行。
- 多依赖升级扩大回归 → 分批记录版本和证据，业务变化升级Human裁决。
- 服务拆分误改事务/状态 → 保留所有者与原子边界，真实并发验证。
- 源目录改变破坏已分享URL → 复用文档站映射，验证产物而不只检查源码链接。
- 本地配置被误用于网络发布 → 本地约束校验和回环发布；不宣称具备生产身份隔离。

## Migration Plan

Human审阅并授权实施后，按tasks分组执行。无数据库迁移；依赖与代码成组回退，目录迁移同时回退构建映射，不回滚用户数据。公开部署必须在发布新版本前显式配置MCP_AUTH_MODE=token，并在相同配置下验证启动；回退旧代码时保持原Token配置。CI中需要认证的套件显式设置token，本地demo单独验证；实际远端配置和发布另需授权。安全及交易相关阶段转换按Git Checkpoint Policy检查；当前停留规划审阅，未进入实施。

## Open Questions

具体依赖目标版本由实施时官方发布记录及兼容验证确定；属于已授权全仓检查内的事实核验。无业务范围待决项；若升级必须改变业务或公开契约，暂停依赖部分提交Human裁决。
