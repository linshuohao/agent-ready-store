## 打开与审阅

用浏览器直接打开 [单一 Design Preview](index.html)，无需安装依赖或启动商城服务。全部 CSS、脚本和商品展示样本位于本目录，没有远程资源或 API 请求。

1. 顶部选择“代表性視覺稿 / 五頁結構線框”，再选择核心页面；视觉模式下购物车与订单结果仍展示原线框，其他三页显示视觉稿。
2. 切换“顾客自行选购”或“Agent 交接”，或点击“開啟 Agent 交接範例”，直接进入同一个 Checkout。
3. 从“頁面狀態”检查异常；用预览宽度按钮检查 1180 / 768 / 390 与自适应布局。预览宽度受到浏览器实际可用空间限制。
4. Checkout →「編輯購物車」→ 将 P001 数量改为 2 →「更新數量」→「前往確認訂單」，检查原购物车标记、Agent 来源和更新报价。
5. 确认按钮只导航至预设结果样本，不下单、不扣库存、不付款。

五页共用 [pages.html](wireframes/pages.html) 及样式/展示脚本，统一入口导航到相应页面；不是为五页建立五个应用。直接打开 pages.html 也可使用页面链接，推荐从统一入口检查状态与说明。

| 页面 | 草稿内容与状态 | 主要依据 |

| 购物车 | 商品/数量编辑、移除操作反馈、预估金额、空车、无效输入、缺货、固定数量调整样本 | UX-03、05；CART-01～06 |
| Checkout | Human/Agent 共享只读摘要、原车编辑入口、明确确认、变价/同总额内容变化/缺货/过期/处理中/结果未明 | UX-04～06、EX-01～03；ORDER-01～06、HAND-01～05 |
| 订单结果 | 完整商品及金额快照、成功、重复提交回原结果；不增加订单长期访问权限 | D-06、21；P-04 |

报价或关键内容变化必须重新展示并再次确认；即使总额不变，商品、数量、单价、优惠、运费或应付金额变化仍须确认。仅库存变化且仍足量不强加再次确认。过期状态没有购买或原凭证恢复入口。缺货状态保留全部条目并阻止提交，不自动部分购买。

过期与成功结果中的“返回商城 / 繼續選購”开启一般选购展示，不带回旧交接购物车；这两种状态的顶部也不提供恢复旧车的入口。避免通过示意导航绕回同一已失效或已完成的交接流程。

## 展示样本的明确限制

- [fixtures.js](wireframes/fixtures.js) 为 30 项 Mock 的只读公开购物字段快照，商品原始名称、规格、描述及评论不改写；不嵌入内部毛利字段。评论始终作为转义后的业务文本呈现，包含伪造指令的内容没有执行权限。
- 默认购物车固定为 P001 × 1、P003 × 1：商品小计 NT$2,580.00，满减 NT$100.00，运费 0；一般来源总额 NT$2,480.00，Agent 折扣 NT$124.00、总额 NT$2,356.00。数字是依据现有规则预先核对的展示常量，没有客户端计价引擎。
- 编辑样本固定为 P001 × 2、P003 × 1；Agent 总额 NT$4,151.50。结果页保留确认页选定的样本组成与金额。
- 变价样本将 P001 展示单价临时设为 NT$1,990.00；同总额样本同时将 P003 设为 NT$590.00。缺货样本将当前可用量展示为 0。它们是明确的合成状态，不修改 Mock 原件，不宣称真实价格或库存变化。
- 商品加购只展示反馈，不将所选商品动态加入固定购物车。移除只展示操作反馈，完整空车在状态选择器查看；不实现通用增删改购物车。数量验证仅展示输入反馈，P001 的 1 → 2 切换固定样本，不承接一般购物逻辑。
- 搜索、分类与排序控件为结构示意，提交后解释展示边界；不实现真实查询。商品展示顺序依据原始推荐分数，示例同分用 ID 排列、每页 6 项；这些是草稿展示安排，不批准 P-02 的同分、筛选、匹配或分页契约。评论每页 2 则及平均分呈现同样是草稿选择，全部评论仍可逐页读取。
- A-示意-01 / H-示意-01 仅帮助评审识别同一上下文，不是真实 ID、凭证或可信来源证明；上方路径切换属于评审工具，不属于商城可伪造来源的产品控件。
- 无 API、状态持久化、真实购物车、库存操作、订单创建或真实金流；没有独立模拟支付步骤，也未加入会员、地址、税费、退款或物流能力。

## 第一阶段验证记录（历史边界）

第一阶段采用现有 `ai-native-review` 的 Design Review / Requirements Conformance 方法，由制作者自查，不称为独立审阅或 Human 验收。其后 Human 已审阅并确认线框结构基础；本轮视觉和 Product Design 的最新验证边界见下方。

可重复运行的展示脚本检查：

```sh
node design/check-preview.cjs
```

此命令在隔离 JavaScript 上下文中生成五页的 46 个页面/路径/状态组合，检查原件哈希、Mock 快照、导航消息、确认/禁止提交状态、固定报价与结果一致性、原车编辑上下文、分页、空车/库存/过期/重试、资源路径及重复 ID。它是静态结构和有限展示状态检查，**不渲染 HTML，不等于浏览器自动化或业务测试**。

第一阶段实际渲染尝试未完成：可用 Playwright 未附带浏览器运行文件；现有 Chrome 在当时执行权限下启动失败；浏览器工具因 `file:` 协议策略拒绝打开原件 HTML。未绕过该原件文件访问限制，第一阶段没有取得可用于验收的截图。

当时的桌面/移动实际布局、溢出、字体效果、焦点顺序与视觉可访问性均为 Unverified；该历史状态不代表本轮视觉稿仍无法在浏览器查看。

静态契约核对未发现需重开已确认方向的阻塞性冲突。HTML 参考中“总额变化”的示意提示没有覆盖总额不变但内容变化的全部条件；本稿按 Requirements 的直接 Human 确认提供独立状态，不将示意文案解释为范围缩减。
